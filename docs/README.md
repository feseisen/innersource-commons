# docs/ — 未収録

**このフォルダはまだ空です。**

設計の本体（設計書、画面モック、作る側／使う側それぞれの手順書）は、まだここに載せていません。
載せるには、特定の組織の事情に依存した記述を一般論に書き換える作業が要るためです。

## 載せる予定のもの

- **設計** — 全体構成と、なぜその構成にしたか
- **手順書** — 作る側（組み立てて配る人）と、使う側（ボタンを押すだけの人）に分けたもの
- **画面モック** — カタログ画面と、投稿から公開までの流れ

## 書き換えの基準

**残すもの**（どの組織でも成立する）

- 設計思想（作り手が報われる／順位をつけない／素人が使う／サーバーを立てられない）
- 画面の流れと、そう置いた理由
- 作る側と使う側を分けた手順の構成

**落とすもの**

- 特定の組織が分かる記述（組織名、部署名、事業の内容）
- 導入先の権限・環境の具体（誰が何を使える、どの機能が許可されている）
- 既存システムの名前、運用ルール、人事に関する話
- 実在の資産名・テンプレート名・氏名（デモ用のものに差し替える）

**判断に迷ったら落とす。** 設計思想は落としても書き直せますが、
一度出してしまった情報は取り消せません。

その間も、[README](../README.md) に設計の考え方の要点は書いてあります。
